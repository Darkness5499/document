


# Daily English Communication Topics for Remote Software Developers

## 1. Daily Stand-up

-   What I worked on yesterday
-   What I'm working on today
-   Blockers and dependencies
-   Asking for help

Example:

-   Yesterday I finished...
-   Today I'll continue...
-   I'm blocked by...
-   Could someone help me with...?

----------

## 2. Task Discussion

-   Clarifying requirements
-   Estimating tasks
-   Breaking down work
-   Confirming priorities

Example:

-   Could you clarify this requirement?
-   What's the expected behavior?
-   Should we prioritize this first?

----------

## 3. Asking Questions

-   Technical questions
-   Business questions
-   API questions
-   Environment/setup issues

Example:

-   I'm not sure I understand...
-   Could you explain...?
-   Do we already have an API for this?

----------

## 4. Code Review

-   Explaining implementation
-   Suggesting improvements
-   Requesting changes
-   Approving PRs

Example:

-   I left a few comments.
-   Looks good to me.
-   Could you simplify this logic?
-   Please add some unit tests.

----------

## 5. Pair Programming

-   Sharing ideas
-   Explaining code
-   Solving bugs together

Example:

-   Let's debug it together.
-   Can you share your screen?
-   I think the issue is here.

----------

## 6. Bug Investigation

-   Reporting bugs
-   Reproducing issues
-   Root cause analysis
-   Suggesting fixes

Example:

-   I can reproduce it.
-   The issue occurs when...
-   I found the root cause.

----------

## 7. Asking for Help

-   Technical support
-   Environment issues
-   Business clarification

Example:

-   Could you take a look?
-   I need a second opinion.
-   I'm stuck on this issue.

----------

## 8. Giving Progress Updates

-   Feature progress
-   Current status
-   Remaining work

Example:

-   The feature is almost done.
-   I'm about 80% finished.
-   I'm waiting for QA.

----------

## 9. Discussing Design

-   Architecture
-   Trade-offs
-   Performance
-   Scalability

Example:

-   What do you think about this design?
-   Should we cache this?
-   Is this approach scalable?

----------

## 10. Sprint Planning

-   Task estimation
-   Story points
-   Capacity planning
-   Sprint goals

Example:

-   I think this is a 5-point story.
-   We can finish it this sprint.

----------

## 11. Sprint Review / Demo

-   Demonstrating features
-   Explaining business value
-   Gathering feedback

Example:

-   Let me show you the new feature.
-   Any feedback?

----------

## 12. Retrospective

-   What went well
-   What didn't
-   Improvement ideas

Example:

-   We should improve our testing.
-   Communication could be better.

----------

## 13. Meetings

-   Team meetings
-   Technical discussions
-   Decision making

Example:

-   Can we schedule a quick call?
-   Let's discuss this offline.

----------

## 14. Documentation

-   Writing technical docs
-   Updating Confluence
-   Writing ADRs
-   Creating RFCs

Example:

-   I'll document this decision.
-   Please update the wiki.

----------

## 15. Deployment

-   Release status
-   Production deployment
-   Rollback
-   Monitoring

Example:

-   The deployment succeeded.
-   Production is healthy.
-   We rolled back the release.

----------

## 16. Incident Handling

-   Service outage
-   High latency
-   Error investigation

Example:

-   The service is down.
-   CPU usage is high.
-   We're investigating.

----------

## 17. Async Communication (Slack / Teams)

Remote teams increasingly favor **asynchronous communication** over meetings.

Typical topics:

-   Status updates
-   Design discussions
-   Technical questions
-   Decision records
-   Sharing documents
-   Sharing meeting notes

Best practices repeatedly recommended by engineering leaders include:

-   Write clearly and concisely.
-   Share context, not just status.
-   Prefer documentation before scheduling meetings.
-   Escalate to a call only when text becomes inefficient.

## 1. Giao tiếp bất đồng bộ qua Slack/Teams (Asynchronous Chat)

_Nguồn từ các bài viết văn hóa remote trên LinkedIn khuyên rằng: "Đừng chỉ chào 'Hi/Hello' rồi im lặng chờ phản hồi (No-Hello policy). Hãy đưa đầy đủ ngữ cảnh ngay lập tức."_

-   **Chủ đề: Báo cáo trạng thái công việc (Status Updates - No Ping)**

    -   _Ngữ cảnh:_ Nhắn tin đầu ngày hoặc khi hoàn thành một task để team nắm thông tin mà không cần họp.

    -   _Mẫu câu:_ _"Hi team, just a quick update: The bug fix for the user login flow is now ready for review. You can find the PR link below. Heading out for lunch now, back in an hour."_

-   **Chủ đề: Đặt câu hỏi chặn (Blocker Questions) kèm giải pháp đã thử**

    -   _Ngữ cảnh:_ Khi bạn bị kẹt ở một vấn đề kỹ thuật và cần hỏi đồng nghiệp từ xa.

    -   _Mẫu câu:_ _"Hey [Name], I'm having an issue with the Docker container building locally. I’ve already tried clearing the cache and rebuilding, but the error persists. Do you have any pointers when you have a moment?"_


## 2. Giao tiếp trong các buổi họp Định kỳ (Scrum/Agile Rituals)

_Nguồn từ các chuyên gia Agile trên LinkedIn nhấn mạnh: Lập trình viên remote cần giao tiếp mang tính "kết quả và hành động" (Outcome-oriented)._

-   **Chủ đề: Trả lời câu hỏi "What are you working on?" trong Daily Standup**

    -   _Ngữ cảnh:_ Báo cáo 3 việc: Hôm qua làm gì, hôm nay làm gì, có gặp khó khăn gì không.

    -   _Mẫu câu:_ _"Yesterday, I focused on writing unit tests for the notification service. Today, I’ll be working on integrating the third-party payment gateway. No blockers so far."_

-   **Chủ đề: Đóng góp ý kiến cải tiến trong họp Sprint Retrospective (Họp cải tiến sau mỗi Sprint)**

    -   _Ngữ cảnh:_ Đưa ra nhận xét về những điều tốt và chưa tốt trong quy trình làm việc remote của team.

    -   _Mẫu câu:_ _"I think our communication during the last deployment went really well. However, for the next sprint, it would be great if we could update the Jira tickets more frequently to avoid confusion."_


## 3. Thảo luận Kỹ thuật & Đánh giá Code (Technical Discussions & Code Reviews)

_Nguồn từ các bài viết trên Medium Tech: "Code review là để cải thiện code, không phải để chỉ trích con người."_

-   **Chủ đề: Nhận xét PR (Pull Request Comments) mang tính xây dựng**

    -   _Ngữ cảnh:_ Bạn để lại ghi chú trên GitHub/GitLab yêu cầu đồng nghiệp sửa code.

    -   _Mẫu câu:_ _"Great implementation! Just a minor suggestion: could we extract this logic into a helper function to improve readability? What do you think?"_

-   **Chủ đề: Tiếp thu phản hồi (Handling Feedback) khi được review code**

    -   _Ngữ cảnh:_ Đồng nghiệp bắt lỗi trong code của bạn và bạn ghi nhận để sửa.

    -   _Mẫu câu:_ _"Good catch! I completely missed that edge case. I will update the logic and push a new commit shortly. Thanks!"_
